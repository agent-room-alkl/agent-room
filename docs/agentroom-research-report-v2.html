Agent Room 产品路线 v2：从 MCP-native 会议层到 Live Session Templates

本报告是对 2026-04-29《AI Room — 竞品调研与产品路线 v0》的复盘升级。Codex 与 Claude 共同确认： 原定位仍然成立，但下一阶段应拆成两条主线：Asset Layer 做厚，Template Layer 做深。

结论：可行，应该做 顺序：先 A 后 B 定位：meeting layer + asset layer 签字：Codex + Claude

最终结论

Agent Room 不应变成 agent runner、workflow canvas 或 HR 工具。 它最自然的定位仍然是：任何 MCP agent 与人类都能进入同一个房间完成结构化协作，并把过程沉淀成可分享、可复用、可签收的报告资产。

4/29 报告的核心判断没有过期，反而被过去十天的项目进展验证了：`room_export`、report page、artifact tags、presence、 MCP 自动安装、Codex hook 持续监听都已经上线到 0.20.3。现在要做的不是改方向，而是把方向升级成 v2 roadmap。

发散后的市场判断

MCP 更像事实标准 OpenAI、Anthropic、Cursor、Codex 等生态都在围绕 MCP 或 MCP-style tool integration 发展。Agent Room 的 MCP-native 定位更强。
编排层被大厂压缩 如果做 agent runner / workflow / sandbox，很容易撞上 Vercel、OpenAI、Cursor、agentsroom.dev 等更重产品。
语音 AI 打开新窗口 OpenAI Realtime API 与 LiveKit Agents 等基础设施让实时 voice agent 变成可落地能力，支撑 Live Session Templates。

收敛：v2 Roadmap

Track A — Asset Layer 做厚

本周优先

这是确定性主线。它直接增强现有用户价值、传播闭环和商业化表达，且大部分依托现有代码，每个子项都可小步快跑。

  • Save & Share CTA：ended room 主按钮，推动用户导出报告。
  • Permanent report link：导出报告摆脱 24h TTL，形成真正资产。
  • OG meta / 分享缩略图：让报告链接在社交渠道看起来像产品 demo。
  • Report 内 CTA：`Create your own room with these agents`，把报告变成获客入口。
  • Artifact 渲染升级：从 transcript dump 升级为决议链、证据链、action items。

Track B — Template Layer 做深

下周 spike

这是增长主线。它把 Agent Room 从“多 agent 开会”抽象到“structured AI sessions”，但应先窄版验证，不宜直接做大。

  • Template 抽象：roles + prompt pack + artifact schema。
  • AI Interview：第一个 Live Session Template，不是 HR pivot。
  • per-template roles：替代全局 6-role preset。
  • 后续扩展：AI coaching、customer research、sales qualification、standup、postmortem。
  • 先 spike voice bridge，再决定是否投入完整 demo。

为什么必须先 A 后 B

维度 Track A Asset Layer Track B Template Layer
确定性 高 已有产品基础，工程短，市场风险低。 中 上限高，但需要验证 template 与 voice agent 链路。
周期 每个子项通常 ≤1 天。 AI Interview voice demo 约 2-3 周。
价值 立刻让现有会议变成可分享交付物，强化 viral loop。 打开更大市场：coaching、research、sales、interview 等 structured session。
风险 主要是报告质量和永久存储设计。 实时音视频、voice AI、成本、隐私、场景聚焦。
执行建议：本周做 Track A，把现有价值闭环做扎实；下周开 Track B 的 voice bridge spike。A 是兜底，B 是高上限机会。

角色预设修正：从全局 6 角色到 per-template roles

4/29 报告提出 6 个默认角色：Facilitator、Researcher、Skeptic、Builder、Writer、QA-Reviewer。 v2 判断是：这 6 个适合 dev/research collaboration，但不应成为全局默认。正确方向是每个 template 自带角色集合。

Template 推荐角色 Artifact expectation
Dev Collaboration Facilitator / Builder / Reviewer / Writer delivery report、decisions、TODOs、implementation notes
AI Interview Interviewer / Candidate / Observer / Evaluator scorecard、evidence、hire/pass recommendation
Customer Research Researcher / Customer / Synthesizer research brief、quotes、insights、open questions
Sales Qualification SDR / Prospect / Sales Observer qualification report、pain points、next step
Standup / Postmortem Facilitator / Team / Action Owner timeline、blockers、action items、owners

实施拆分

Phase 1 — Report share loop Save & Share CTA、永久报告、OG meta、报告内创建房间 CTA。
Phase 2 — Artifact quality 决议链、证据、action items、角色贡献、Markdown/HTML clean export。
Phase 3 — Template foundation template schema、per-template roles、prompt pack、artifact schema。
Phase 4 — Live template spike AI Interview voice bridge：candidate audio → AI voice → transcript。

明确不做

不做项 原因
不做 agent runner 执行层已被 Claude Code、Codex、Cursor、Vercel 等工具占据。Agent Room 应做协作层。
不做 workflow canvas / Kanban 会把产品拖向通用工作流平台，失去 meeting layer 的独占定位。
不做 VM execution / screen replay 这是 agentroom.app 的执行回放路线，基础设施重，和当前资产层路线不同。
不做 desktop/mobile shell 入口应保持 browser + MCP。桌面壳会增加分发成本，并和 agentsroom.dev 撞位。
暂不做 完整 auth / agent registry 等外部团队集成和安全需求更明确后进入 P3，不提前增加摩擦。
